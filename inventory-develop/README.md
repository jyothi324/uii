# 📦 Inventory Service

> A backend REST API server built with **Go**, **Gin**, and **GORM** — handling inventory management with full unit test coverage and live-reload development.

---

## 🛠️ Tech Stack

| Layer | Technology |
|-------|-----------|
| **Language** | Go |
| **Web Framework** | [Gin](https://github.com/gin-gonic/gin) — fast HTTP router & middleware |
| **ORM** | [GORM](https://gorm.io) — database interactions, migrations, associations |
| **Live Reload** | [Air](https://github.com/air-verse/air) — hot reload on file changes |
| **Task Runner** | GNU Make — standardized dev commands |
| **API Testing** | Boomerang (see [`/boomerang`](./boomerang/)) |

---

## 🚀 Setup

Install all dependencies and prepare the project in one command:

```bash
make setup
```

This will:
- Download all Go module dependencies (`go mod download`)
- Install `air` for live reload
- Run any required database migrations via GORM
- Prepare environment configuration

> Make sure Go is installed (`go version`) and your database is running before executing setup.

---

## ▶️ Run

### Development (with live reload)

```bash
air
```

`air` watches for file changes and automatically rebuilds and restarts the server. Config is in `.air.toml`.

### Without live reload

```bash
go run main.go
```

### Build binary

```bash
go build -o bin/inventory .
./bin/inventory
```

## 🌍 Environment Configuration

Environment variables are stored in a `.env` file at the project root. **Never commit this file.**

```env
# Server
APP_PORT=8080
APP_ENV=local          # local | qa | production

# Database
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=your_password
DB_NAME=inventory_db

# JWT / Auth (if applicable)
JWT_SECRET=your_jwt_secret
```

Copy the example file to get started:

```bash
cp .env.example .env
```

To switch environments (e.g. QA), update the values in `.env` or export them directly:

```bash
APP_ENV=qa DB_HOST=qa.db.internal air
```

## 🧪 Testing

### Unit Tests

Run tests and get a **percentage coverage summary** in the terminal:

```bash
make check-coverage
```

Get a **visual HTML report** showing exactly which lines are covered:

```bash
make check-coverage-html
```

This generates `coverage.html` — open it in a browser to see coverage highlighted line-by-line across every file.

#### What these commands run under the hood

```bash
# check-coverage
go test ./... -coverprofile=coverage.out
go tool cover -func=coverage.out

# check-coverage-html
go test ./... -coverprofile=coverage.out
go tool cover -html=coverage.out -o coverage.html
```

#### Run tests directly

```bash
# Run all tests
go test ./...

# Run tests in a specific package
go test ./services/...

# Run a specific test by name
go test ./... -run TestInventoryService_GetAll

# Run with verbose output
go test ./... -v

# Run with race condition detector
go test ./... -race
```

#### Example unit test (Gin + GORM pattern)

```go
// services/inventory_test.go
package services_test

import (
    "testing"
    "github.com/stretchr/testify/assert"
    "github.com/stretchr/testify/mock"
)

func TestGetInventoryByID_Found(t *testing.T) {
    mockRepo := new(MockInventoryRepository)
    mockRepo.On("FindByID", uint(1)).Return(&models.Inventory{ID: 1, Name: "Widget"}, nil)

    svc := services.NewInventoryService(mockRepo)
    result, err := svc.GetByID(1)

    assert.NoError(t, err)
    assert.Equal(t, "Widget", result.Name)
    mockRepo.AssertExpectations(t)
}

func TestGetInventoryByID_NotFound(t *testing.T) {
    mockRepo := new(MockInventoryRepository)
    mockRepo.On("FindByID", uint(99)).Return(nil, gorm.ErrRecordNotFound)

    svc := services.NewInventoryService(mockRepo)
    result, err := svc.GetByID(99)

    assert.Nil(t, result)
    assert.ErrorIs(t, err, gorm.ErrRecordNotFound)
}
```

> 💡 **Best practice:** Aim for >80% coverage on `services/` and `repositories/`. Handlers are better tested via API tests in Boomerang.

### API Tests — Boomerang

All API endpoint tests are located in the [`boomerang/`](./boomerang/) folder.

Import the collection file into **Boomerang** to run full API test scenarios against a live server instance:

1. Open Boomerang
2. **Import** → select the `.json` file from `./boomerang/`
3. Set the base URL to your environment (e.g. `http://localhost:8080`)
4. Run the collection
